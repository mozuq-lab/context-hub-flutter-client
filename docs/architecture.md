# 構成と制限

Markdown Vaultが正本です。Dartが上限付きsnapshotの読取・検索・context作成・操作管理を担当し、Swift/Kotlinの限定MethodChannelがOSのファイルアクセスを担当します。Nodeは本体とのprotocol互換性を開発時に検査するためにだけ使い、端末アプリには同梱しません。

## データの読取

読取は1ファイル1MiB、合計64MiB、読む.md/.jsonファイル20000件（フォルダーや対象外のファイルを含む走査は100000エントリー）、深さ12までです。本体の整理・受付の回復用記録（`90_system/receipts/pending`・`receipts/events`・`intake/pending`）、再関連付けの表示完了記録（`association-views`）、プロジェクト承認の確認・反映途中の記録（`project-confirmations`・`project-approvals/materialized`）はアプリのどの画面も使わないため、数えず読みません（一覧はDartの`snapshotSkippedPaths`で、ネイティブへ渡します）。これらを除くと、端末からのメモ1件あたりの読取は約4ファイルで、数千件のメモまで読み切れます。表示の再読込（保存後や再読込ボタン）は、前回の読取で得た更新時刻と大きさが一致するファイルを読み直さず、前回の本文を引き継ぎます。時刻の粒度が粗い保存先（FAT32の2秒など）で同じ時刻・同じ大きさの書き換えを見逃さないよう、読取開始の3秒前より新しいファイルは引き継ぎの対象にしません。contextコピー・候補の採用・状態変更などの依頼の前の確認は、全体を読み直します。上限に達した場合は、各画面の先頭に表示が不完全になる旨を示します。原文hash、訂正、生成物、候補一覧の依存hashを検査し、不明な状態ではcontextコピーや候補操作を停止します。方針の意味上の比較はJSONのキー順に依存しません。

contextコピーには共通と対象プロジェクトの有効方針を全文含めます。コピー前にsnapshotを再検査し、コピー中に到着した適用停止・承認記録も独立した再走査で検出します。未同期や容量上限による欠落を、反映済みとして扱いません。

Vault直下は、共通の有効方針`POLICY.md`と、本体が生成するふりかえり`REVIEW.md`だけを読みます。`REVIEW.md`は生成hashを照合し、手動変更や同期途中の可能性があれば注意を表示します。プロジェクトの停滞は、NOWの最終根拠から本体の既定と同じ14日を超えたかで判断します。

検索は本体の`ctx find`と同じく、NFKC・小文字化した語をすべて含む記録を一致数の多い順に並べます。プロジェクトの絞り込みも本体と同じ規則で、本人が指定した帰属・NOW・プロジェクトの知識を確定、整理結果の関連候補（確信度0.7以上）をAI推定として区別し、アイデアは元のメモの帰属に従い、共通の知識は含めません。期間と新しい順は、原文とアイデアは発生日時、NOWは最終根拠の日時、知識は生成日時で判断します。分類を取り消したアイデアは種類の絞り込みに含めません。

プロジェクト状態の変更依頼は、表示中の`project.md`のhashに結び付けます。依頼直前に再読込し、定義が変わっていれば保存しません。本体は同じhashのときだけ反映します。

新しいプロジェクトの作成依頼（`project-create`）は、フォームを開いたときに本体のプロジェクト案と同じ`project-<ULID>`形式のIDを決め、名前・別名・キーワードと任意の最初のメモ（本文）を送ります。名前・別名が既存のプロジェクトや作成依頼中のプロジェクトと重なる場合は、本体と同じ判定（NFKC・小文字化）で保存前に止めます。定義が同期されるまでは、メニューに「作成依頼中」として表示します。

NOWの自動領域が手で書き換えられ、本体が新版を`90_system/conflicts/NOW.<id>.<ULID>.md`へ退避している場合は、プロジェクト画面に「NOWの更新が止まっています」と、手で変えた行を表示します。行は本体が最後に書いた自動領域（`90_system/now-generated/<id>.json`）と比べ、基準がない旧版では最新の退避と比べます。「生成版に戻す」は表示中の`NOW.md`のhashに結び付けた`conflict-resolve`依頼で、本体は手で変えた行をメモとして残してからNOWを作り直します。

## 依頼の保存

アプリは本人が確認したメモ・作業要約・採用・却下・適用停止・プロジェクトの作成・プロジェクト状態変更・プロジェクトの名前・別名・キーワードの変更・NOWを生成版に戻す依頼・NOW項目の完了報告・誤りとして外す報告と期日・見直す日の依頼・作業記録の下書きの見送り・メモの訂正の要求だけをInputへ新規保存します。訂正は訂正チェーンの最新の入力IDを対象にし、依頼直前に再読込して新しい訂正が届いていれば保存しません。反映待ちの訂正がある間、同じメモへ重ねて訂正しません。本体が古い対象として断った場合は、受付失敗の理由（`stale-correction-target`）と最新のIDを受付状況に示します。完了報告と期日・見直す日の依頼はNOWと同時に本体が書く項目一覧（`90_system/now-items/`）のキーに結び付け、日付の依頼は変更後の期日と見直す日の全体（両方nullで外す）を`operation: item-schedule`で送ります。下書きから作る入力には下書きIDとhashを付けます。誤りとして外す報告は、完了報告と同じ`operation: item-resolution`に`action: exclude`と理由（`reason`: `misread`・`wrong-project`・`outdated`）、任意の一言（`note`、1行・200文字以内）を付けて送ります。本体が読み直した結果（`90_system/item-rereads/`）と「別のプロジェクトの話」として外した記録は、メモとプロジェクトの関連（検索の絞り込み、文脈の「関連候補」）を本体と同じ条件で読むために使います。バックアップの確認結果（`90_system/backup-checks/`）は読むだけで、最後の確認と最後に復元できた確認から、ホームの「最後に確かめた復元点」を作ります。前回見てからの変化は、プロジェクトごとに最後に開いたときのNOWの行を端末の`settings.json`に保存して比べます。プロジェクトのピン留めと並びも、Vaultごとに端末の`settings.json`（`pins`）へ保存し、Vaultには書きません。「次の一手」画面は、進行中のプロジェクトのNOWの「次の一手」「未解決」を、ピン留めしたプロジェクトから順に、残りは最終根拠が新しい順に集めて表示するだけで、新しいファイルは読みません。期日が過ぎた・今日・7日以内の項目を先頭に、見直す日が先の項目を末尾にたたんで示します。区分と「今日」「1週間後」などの入力候補は、項目一覧の`schedule`と日本時間の暦日で決めます（本体の設定がタイムゾーンをAsia/Tokyoに固定しているため、端末のタイムゾーンに関わらず本体のHOMEと同じ日になります）。完了・解決の報告が反映待ちの項目には、日付を依頼できません。この画面を開いても既読にはしません。プロジェクトの経緯は本体が生成する`10_projects/<id>/HISTORY.md`を読んで表示するだけです。名前・別名・キーワードの変更は、状態変更と同じく表示中の`project.md`のhashに結び付け、変更後の全体を`operation: project-definition`で送ります。反映待ちの間は、同じプロジェクトへの状態変更・定義変更を重ねて依頼できません。書きかけのメモは、Vaultではなくアプリ専用領域の`drafts.json`に残します。文脈かごは記録のIDだけを`basket.json`に残し、コピーの直前に出典付きcontextのコピーと同じ手順でVaultを読み直してから文章を作ります。Inputへは何も書きません。正式データの作成と整理はMini側の本体が行います。

固定UUIDからREQ IDを決め、本文を含まないjournalへfingerprint・保存先・日時を先に記録します。同じ操作は再送せず確認だけを行います。未確定保存の本文は開いたフォームで保持し、再起動後の未保存本文復元は保証しません。

MacはNOFOLLOW・排他公開・file/dir fsyncを使います。保存先識別はbookmarkのバイトと分け、volume UUID（取得不可時はdevice番号）とinodeを使います。フォルダーのコピーは別Vaultです。AndroidのjournalはO_EXCLとfile/dir fsync、SAFのInputは一時ファイル・fsync・rename・本文readbackを使います。

## 選んで深掘り

`lib/core/guided.dart`が、Claude APIへ送る依頼の組み立てと出力の検証、`lib/ai/claude_client.dart`がMessages APIへのHTTPS送信、`lib/app/guided_controller.dart`が進行（開始・回答・戻る・まとめ・保存）を担当します。1回の呼び出しでは、深掘りの間変わらない資料（キャッシュの印付き）と、目的・きっかけ・それまでの問答を1つのメッセージにまとめて送り、会話の履歴は持ちません。プロジェクトの名前とIDは、資料を送るときだけ依頼に入れます。出力はJSON Schemaで形を決め（構造化出力）、選択肢の数・長さ・画面に常にある操作との重なりを検証して、使えない出力は理由を添えて1回だけ作り直します。応答の打ち切り（`refusal`・`max_tokens`）やHTTPの失敗は、APIキーを含まない案内にします。安全上の理由での辞退は、サーバー側の代替（`fallbacks: "default"`）で別のモデルが答えることがあります。

まとめは目的ごとの見出しのMarkdownに書き直し、問答の記録（AIの選択肢から選んだ答えと本人の言葉を区別）はアプリが決まった形で付けます。保存は通常のメモ（`operation: capture`、`kind: memo`）で、`meta`に`capture_mode`・`guided_purpose`・`guided_questions`・`guided_model`・`guided_context`を文字列で付けます（本体の入力形式に合わせる）。操作ID・journal・保存結果が不明なときの確認は、メモの追加と同じです。途中の状態は`guided.json`（深掘り1件・今月の利用・月の上限）に残し、操作journalとしては扱いません。APIキーはネイティブの`readSecret`・`writeSecret`・`deleteSecret`（名前は`anthropic-api-key`だけ）で、Macはキーチェーン、AndroidはAndroid Keystoreの鍵で暗号化したファイルに保管します。キーは深掘りの画面を開いたときに読み、閉じるまで`GuidedController`のメモリに持ちます。読み出せないとき（キーチェーンでの拒否など）は、キーがないときと分けて案内します。別のVaultで保存結果が不明な深掘りが残っている間は、本人が破棄を選ぶまで新しく始めません。

## 秘密情報らしい文字列

`lib/core/secrets.dart`は、本体の`packages/core/src/secrets.ts`と同じ規則（既知の形式、`password=`のような代入の値、高エントロピーな文字列）で検出します。同じ結果になることを、本体の試験データ（`vendor/context-hub/packages/core/test/fixtures/secret-cases.json`）で確かめます。本体の規則を変えたときは、この試験が失敗するのでDart側も合わせます。設定で追加した本体の規則（`privacy.patterns`）はアプリには反映されません。保存の前の確認は知らせるだけで、原文を勝手に書き換えません。

組み立てた文書は、部分ごと（メモの本文、きっかけ、回答）に伏せてから組み立て、最後に1行ずつ確かめます。全体を一度に伏せると、終わりのない秘密鍵の見出しが後ろの内容まで消すためです。contextの抜粋は、切る位置の先まで余裕を持たせた範囲を検査してから切ります。文脈かごのコピーは、本体の`ctx bundle`と同じく、記録の本文・有効解釈・NOWの自動領域・方針をそれぞれ伏せてから組み立てます。端末向けのビルドでは、空白のない数万文字の並びで正規表現が後戻りの上限に達することがあり、その場合は値を出さない側に倒して全体を「検査できない長い文字列」として伏せます。

## 似ているアイデア

本体が書く`90_system/idea-index.json`（似ている組の候補、束、束を直接つなぐ判断の組）を読みます。束ねる・別の話にする依頼は`operation: idea-link`で、確認の画面を出した時点の両方のアイデアのhashを付けます。保存の直前に読み直した内容がそのhashと違う場合や、索引とアイデアの同期が揃っていない場合は、依頼を保存しません。保存した後にアイデアが作り直されていた場合は、本体が依頼を受け付けず、受付状況に理由を示します。受理された依頼は、その判断の記録（`90_system/idea-links/`）より後に作られた索引が届くまで反映待ちとして扱い、同じ組への操作を止めます。後からCLIや別の端末で逆の判断がされた場合は、索引の今の状態をそのまま表示します。

## ホーム画面ウィジェットとショートカット（Android）

`lib/core/home_widget.dart`が、読込済みの記録から表示用の短い文字列（題名・件数・次の一手の行・読込時刻）を作り、読込のたびにネイティブへ渡します。ネイティブ（`HomeScreen.kt`）はそれをアプリ専用のSharedPreferencesに置いて並べるだけで、Vaultを読みません。定期更新はしないため、表示はアプリで最後に読み込んだ時点の内容です。表示設定（本文を出すか、対象のプロジェクト）は`settings.json`にVaultごとに保存します。選んだプロジェクトが進行中でなくなった場合は、ほかのプロジェクトへ広げずに何も出しません。

ウィジェットの次の一手は、「次の一手」画面と同じ区分で、期日が7日以内の項目を先に並べ、見直す日が先の項目を数えず出しません（区分は読込時点の日本時間の暦日で決め、次に読み込むまで変わりません）。

ショートカットとウィジェットは、開く画面（メモを追加・選んで深掘り・次の一手）を指定してアプリを起動するだけです。保存や依頼は通常の画面と同じ確認を通ります。入力・保存・確認の画面を開いている間に届いた指定は、割り込まずに開けなかったことを知らせます。記録の詳細などを開いているときは、その上に開きます（「次の一手」は一覧へ戻ります）。ショートカットは、開いている画面を作り直さないよう起動時に登録します（Android 7.1以降）。Macには対応する機能がありません。

## OSと運用の範囲

対象はApple SiliconのmacOS 12以降とAndroidです。Macのsecurity-scoped bookmark、AndroidのローカルExternalStorageProviderのSAF権限を利用します。全ストレージ権限・クラウドprovider・SQLite・新規サーバーは利用しません。

同期・モデル・Gateway・常駐サービスをアプリから操作しません。ネットワークへの接続は、選んで深掘りのClaude APIへの依頼だけです。Macのbundle IDは `com.mozuqlab.contexthub.flutter`、Androidは `com.mozuqlab.context_hub_client` です。

OSフォルダー選択と再起動後の権限保持、実端末・実同期などの確認範囲は[検証状況](verification.md)、データ保全と復旧は[SECURITY.md](../SECURITY.md)を参照してください。
