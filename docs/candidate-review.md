# 候補を確認して採用する

ホームの「確認待ち」または左側メニュー（Androidでは左上メニュー）の「確認待ち」を開きます。

- 確認待ち：プロジェクト案・知識・判断や方針・好みの未承認候補です。
- 要確認：根拠が訂正された候補、破損、同期不足などです。この状態から採用・却下はできません。
- 判断履歴：採用・却下した内容です。承認記録と反映先の両方が届くまで反映済みとは表示しません。

候補を開くと主張、理由、日時、元のメモと訂正履歴、置き換え元を確認できます。「元のメモを開く」では通常の記録画面へ進みます。AI候補は本人が採用するまで正式知識・プロジェクト定義になりません。

「採用する」「却下する」を押すと確認画面が開きます。内容を確認し「採用を依頼」「却下を依頼」を押してください。保留は「保留して閉じる」、確認の取消は「取消」です。どちらも依頼を保存しません。

依頼はこの端末の `Input/REQ-….md` に新しく保存します。同期後にMiniが最新状態を再検証します。「依頼保存済み・Miniの判断待ち」と「承認済み・反映済み」は別の状態です。受付状況と判断履歴を再読込して確認してください。別端末で同じ判断をしても正式データは増えず、反対の判断は先に確定した記録が優先されます。

保存結果が不明な場合は再送せず、受付状況の保存確認を使います。確認中に同期内容やVaultが変わると操作を止め、再確認を求めます。候補の本文が同じでも元メモに新しい訂正があれば、Miniでの再整理を待ちます。既存REQや候補、承認記録を直接編集しないでください。

この機能には候補一覧を生成できる本体とQuickAddの対応版が必要です。本体の `dashboard` または `cycle` が `90_system/review/index.json` と必要な分割pageを更新します。一覧が未同期なら同期とMini側の更新を確認してください。ObsidianのHOMEとQuickAddも同じ一覧・判断記録を使います。

アプリ専用サンプルは初回作成後に上書きしません。以前の版で作ったサンプルには新しい候補が追加されないため、候補の確認には対応本体で作成した架空Vaultを選択してください。実Vaultの初期化やアプリデータの削除で代用しないでください。
