# ContextHub Flutter

[ContextHub](https://github.com/mozuq-lab/context-hub)のVault（Markdownのフォルダー）を、MacとAndroidで読んだり、メモを追加したりするためのアプリです。

ContextHubは、AIとの作業要約や日々の思いつきをMarkdownに集め、Mac mini上の本体が「現在地・次の一手・未解決」に整理する仕組みです（アプリの画面では、このMac miniを「Mini」と表示します）。このアプリは、その整理結果を手元の端末で確認し、新しいメモや判断の依頼を送る窓口です。整理そのものは行いません。

- 対応OS: Mac（Apple Silicon、macOS 12以降）、Android
- 対象外: iPad/iOS、Intel Mac
- 現在の版: 0.3.0
- 検証状況: Androidはエミュレーターで、Macは実アプリでサンプルの閲覧・保存・候補操作を確認済みです。Macのフォルダー選択と再起動後の権限復元、実機のAndroid端末、実際の同期は未検証です。詳しくは[検証状況](docs/verification.md)を参照してください。
- ライセンス: MIT

## できること

- **プロジェクトの現在地を見る**: プロジェクトごとの「現在地・次の一手・未解決・提案」を表示します。要約から元のメモ（原文）と出典・日時へたどれます。
- **最近のメモ・アイデアを見る**: 最近追加されたメモや、整理されたアイデアを一覧で確認できます。
- **検索する**: タイトルと本文を検索します。プロジェクト・種類（メモ・作業要約・訂正・アイデア・知識・NOW・資料）・期間で絞り込め、条件だけで一覧することもできます。一致箇所を強調した抜粋が出て、一致の多い順と新しい順を切り替えられます。プロジェクトで絞り込んだときは、AIが推定しただけの関連に「AI推定の関連（帰属未確定）」と示します。
- **古い記録までさかのぼる**: 最近のメモ・アイデア・検索結果は50件ずつ表示し、「さらに読み込む」で古い記録へ進めます。
- **Mermaidの図を見る**: 記録の本文・プロジェクトの手動メモ・ふりかえりなどに ```` ```mermaid ```` のコードブロックがあると、図（フローチャート・シーケンス図など）として表示します。幅に収まらない図は縮めて全体を見せ、「拡大して見る」で全画面に開いて拡大・移動できます。「コードを見る」で原文も確かめられます。図にできない書き方や大きすぎる図は、理由を添えてコードのまま表示します。図はアプリの中で描き、ネットワークにはつなぎません。
- **元のメモを訂正する**: メモや作業要約の詳細画面の「訂正を書く」から、訂正後の全文を送れます。元のメモは残り、訂正として追加されます。すでに訂正があるメモは最新の訂正に対して書きます。Miniが受け付けなかった場合は、理由を受付状況に表示します。
- **メモの続きを書く**: メモや作業要約の詳細画面の「続きを書く」から、前のメモを残したまま続きを新しいメモとして送れます。プロジェクトを選ばなければ、前のメモで指定したプロジェクトを引き継ぎます（画面に「前のメモと同じ」と示します）。詳細画面では「前のメモ」と「続き」をたどれます。Mac miniのAI読み取りは、前のメモを前提として「さっきの件」のような書き方を読みます。対応した本体が必要です。
- **AIに渡す文脈（context）をコピーする**: 出典付きの文脈をクリップボードへコピーし、別のAIとの会話に貼り付けられます。
- **選んだ記録だけを束ねて渡す（文脈かご）**: 検索結果・最近のメモ・アイデア・記録の詳細で ⊕ を押すと、記録を「文脈かご」に集められます（かごに記録があるとメニューに「文脈かご」が出ます）。プロジェクトをまたいで選べ、並べ替えもできます。「まとめてコピー」で、選んだ順に、出典・訂正の注意（訂正があれば最新の訂正の本文）・AI推定の関連の区別と、関わるプロジェクトの方針を付けた1つの文章になります。本文は囲み（```）に入れ、本文中の見出しが別の記録に見えないようにします。上限（6000・12000・30000字から選択）に収まらない記録は本文の途中で切らずに丸ごと省き、末尾にIDを示します。かごの中身はこの端末の`basket.json`だけに残し、Vaultには書きません。本体の`ctx bundle`と同じ形です。
- **ふりかえりを見る**: 本体が生成する直近の期間のふりかえり（REVIEW.md）で、動いたプロジェクト、「現在地」「次の一手」の変化、持ち越しの未解決を確認できます。
- **止まっているプロジェクトに気づく**: 最終根拠から何日経ったかを表示し、14日を超えて動きのない進行中のプロジェクトを「停滞」と示します。プロジェクトを進行中・休止・完了に切り替える依頼もできます（休止・完了は一覧の後ろにまとめます）。
- **全プロジェクトの次の一手をまとめて見る**: ホームの「次の一手」から、進行中のプロジェクトの「次の一手」と「未解決」を1画面で確認できます。ピン留めしたプロジェクト、最新の根拠が新しいプロジェクトの順に並び、休止・完了のプロジェクトは含みません。終わった項目はその場で完了・解決を報告できます。
- **プロジェクト未定のメモの次の一手を見る**: どのプロジェクトにも結び付いていないメモの行動は、どのプロジェクトの「次の一手」にも出ません。本体が、そうしたメモからAIの「タスク」の分類と次の一手の提案を集め、アプリはホームに新しい3件を、「次の一手」画面の「プロジェクト未定」に新しい順（本体が載せる30件まで、10件ずつ）で並べます。短いメモは本人の言葉、長いメモはAIの要約として示し、元のメモを開けます。分類・要約・提案はAI生成・未検証です。「自分の行動にする」で引き取った行と、プロジェクトを決めずに自分で足した行動には、プロジェクトの項目と同じく期日・見直す日（と繰り返し）・手間の目安を付けられ、期日が近いものは「次の一手」の期日の欄に「プロジェクト未定」として並びます（AIの行のままでは付けられません。Mac miniの本体が対応しているときだけ操作を出します）。メモがプロジェクトに結び付くと、そのプロジェクトの次の一手へ移ります。対応した本体が必要です。
- **今週の気づきを見る**: 本体で週次の統合を有効にすると、本体がたまったメモを週に1回まとめて読み直し、メモ1件を読むだけでは分からないこと（つながり・考えの変化・止まっている意図・次の一手の提案・問い）を返します。アプリはホームの先頭に欄ごとの1件を出し、「ほかN件を表示」で残りも出します。項目ごとに根拠のメモを開いて確かめられ、気づきを作った後に訂正が届いたメモには「訂正あり」と示します。AIの推定（未検証）で、プロジェクトや次の一手は変えません。前回の実行が失敗したときと、間隔を過ぎても新しい結果がないときは、それと分かるように示します。項目ごとに「役に立った」「的外れ」を付けられ（もう一度押すと外します）、問いと止まっている意図には「答える」から答えをメモとして残せます。反応と答えは、本体の次の週の読み直しで使われ、本体のふりかえりに件数が出ます。対応した本体が必要で、本体の既定では無効です（[本体の週次の統合の説明](https://github.com/mozuq-lab/context-hub/blob/main/docs/weekly-synthesis.md)）。
- **ホームで先に見るものを上に置く**: ホームは、今週の気づき（本体で有効なとき）、次の一手、プロジェクト未定の次の一手、プロジェクト、確認待ち、ふりかえり、最近のメモの順に並べ、受付の状況は末尾の1行にまとめます（詳細は「受付状況」）。確認待ちには、AIのプロジェクト案を根拠のメモが多い順に3件まで出し、そのまま内容の確認へ進めます。
- **短いメモは本人の言葉のまま見せる**: 訂正のない100文字以下のメモ1件から作られたアイデアは、一覧と検索結果の題を、AIの言い換えではなく本人の言葉にします。対応した本体は、短いメモの要約そのものを本人の言葉にします。それより前に整理されたアイデアも、アプリが同じ見え方にそろえます（アイデアの本文は書き換えません）。
- **よく見るプロジェクトをピン留めする**: ホームの各プロジェクトのピンの印、またはプロジェクト画面の「ピン留め」で、メニュー・ホーム・「次の一手」の先頭に置けます。ホームの「並び替え」で順番を変えられます。休止・完了のプロジェクトもピン留めでき、メニューとホームでは先頭に出ます（「次の一手」には出ません）。ピン留めと並びはこの端末に保存し、「好みを端末間でそろえる」を有効にしたときだけ、ほかの端末へ伝えます（30件まで）。
- **人ごとに見返す**: メニューの「人」から、よく一緒に仕事をする人や返事を待っている人を、名前と呼び名で登録できます。本体が、その名前が出てくるメモ・作業要約と、プロジェクトをまたいだ未完了の次の一手・未解決を人ごとにまとめ、アプリはその一覧を、元のメモへのリンク付きで表示します。名前の一致は本体がAIを使わずに判定し、登録した人だけが対象です（同じ名前の別人や、名前を含む別の語も拾うことがあります）。名前と呼び名の変更、登録を外す依頼もできます。対応した本体が必要です。
- **書いている途中に、前に書いた記録に気づく**: メモの入力画面で20文字ほど書くと、この端末に読み込んだ記録から、関係ありそうなメモ・作業要約を3件まで入力欄の下に出します。同じことを前に書いていないか、続きの話ではないかを確かめられ、記録を開く（同じ内容なら訂正を書く）、文脈かごに入れる、その記録のプロジェクトで保存する、を選べます。比べるのは端末の中だけで、ネットワークにもAIにも送りません。入力画面の「書いている途中に、関係ありそうな過去の記録を出す」で止められます（端末ごとの設定）。
- **プロジェクトの呼び名とキーワードを手入れする**: プロジェクト画面の「呼び名とキーワード」から、名前・別名・キーワードの変更を依頼できます。AIがメモをどのプロジェクトに結び付けるかの手がかりになります。プロジェクトを指定せずに保存し、まだどのプロジェクトにも結び付いていないメモは、次の整理で新しい定義に合わせて見直されます。
- **プロジェクトの望む結果を書く**: プロジェクト画面の先頭に、本人が書いた「望む結果（何をもって完了か）」を示します。「望む結果を書く」「望む結果を直す」（または「…」の「呼び名・キーワード・望む結果を変える」）から変更を依頼でき、新しいプロジェクトの作成でも書けます。休止・完了に切り替えるときの確認と、停滞しているプロジェクトの表示（ホーム・週次レビュー）にも添えます。望む結果はメモの整理のときにAIへも渡すので、書き換えると、まだどのプロジェクトにも結び付いていないメモは次の整理で見直されます。対応した本体（`intake-features.json`の`project_outcome`）が必要です。
- **今日やるものを3つ選ぶ（今日の3つ）**: 次の一手・未解決の各項目の「今日やる」で、今日手を付けるものを3つまで選べます。選んだ項目はホームと「次の一手」の先頭に「今日の3つ」として並び、そこから完了・解決を報告したり、今日から外したりできます。片付いた項目は打ち消し線で残り、その日に何を片付けたかが見えます。日付（日本時間）が変わった後に開くと、終わらなかった項目を「前の日から持ち越した項目」として示し、「今日も続ける」「期日を付ける」「外す」から選べます。3日続けて持ち越した項目には、小さく分けることを勧める一言を添えます（AIは使わず、日数だけで判断します）。NOWから見つからなくなった項目は、選んだときの本文と一緒にその旨を示します。Androidのホーム画面ウィジェットで本文を出す設定にしていると、今日の3つを先に並べます。選んだ項目はこの端末だけにVaultごとに保存し、Vaultやほかの端末には伝わりません。
- **次の一手・未解決に期日と見直す日を付ける**: 各項目の「日付を付ける」から、期日と次に見直す日を依頼できます（今日・明日・1週間後などのボタンか、YYYY-MM-DDで入力）。「次の一手」画面では、期日が過ぎた・今日・7日以内の項目をプロジェクトをまたいで先頭に出し、見直す日が先の項目は末尾にたたみます。日付はAIが推測せず、本人が付けたものだけです。
- **空いた時間に合う次の一手を選ぶ（手間の目安）**: 各項目の「…」の「手間の目安を付ける」から、「15分ほど」「1時間ほど」「半日以上」を依頼できます。「次の一手」画面の上の「15分でできる」「1時間でできる」「目安なし」で絞り込めます（1時間でできるものには15分でできるものも含めます）。目安は本人が選んだものだけで、AIは推測しません。対応した本体が必要です。
- **今いる場所や手元の道具でできる次の一手を選ぶ（場所・道具の札）**: 各項目の「…」の「場所・道具の札を付ける」から、「家」「外出先」「PC」「電話」のような札をいくつでも依頼できます。「次の一手を追加」でも、手間の目安と札を一緒に選べます。「次の一手」画面の「場所・道具」で、プロジェクトをまたいで札の付いた項目だけ、または「札なし」の項目だけに絞り込めます（手間の目安の絞り込みと重ねられます。絞り込んでも、期日が近い項目は期日の欄として先頭に出ます）。選べる札の一覧は「札の一覧を編集」で足す・外す・並べ替えができ、Vaultに置いて同じVaultを使うすべての端末で共有します。一覧から外した札は、付いている項目に残ります。札は本人が付けたものだけで、AIは付けません。対応した本体が必要です。札の一覧を初めて編集する前に、同じVaultを使うすべての端末のアプリを更新してください（古いアプリは、札の一覧を含む好みの記録を読めず、ピン留めなどの好みを取り込めなくなります）。
- **人に頼んだことを「連絡待ち」にする**: 次の一手・未解決の項目（プロジェクト未定の自分の行動を含む）の「…」の「連絡待ちにする」から、相手（任意・40文字まで）と頼んだ日を依頼できます。連絡待ちの項目は「次の一手」画面の下の「連絡待ち」にまとまり、次の一手の件数とホーム画面のウィジェットから外れます。見直す日を付けると、その日から画面の先頭の「連絡待ちの確認」に出ます。相手の名前はVaultの項目一覧に残り、この画面と本体のHOME・ふりかえりにだけ出ます（ウィジェット・通知と、別のAIに渡すNOWには載せません）。印は本人が付けたものだけで、AIは付けません。対応した本体が必要です。
- **今は取り組まないことを「いつかやる」に置く**: 次の一手・未解決の項目（プロジェクト未定の自分の行動を含む）の「…」の「「いつかやる」へ移す」から、項目を「いつかやる」へ移せます（連絡待ちの項目は先に印を外します）。移した項目は次の一手・未解決の件数とホーム画面のウィジェットから外れます。メニューの「いつかやる」画面には、移した項目・休止中のプロジェクト・本人が置いたアイデア（アイデアの画面の「「いつかやる」に置く」）が、最後に見直した日の古い順に並び、行ごとに「始める・そのまま・やめる」を選べます。ホームには件数と、30日以上見直していない件数が出ます。移す・置く・見直すのは本人だけで、AIは決めません。対応した本体が必要です。
- **週次レビューを手順に沿って進める**: 「ふりかえり」の先頭の「週次レビューを始める」から、確認待ち・プロジェクト未定の行動・進行中のプロジェクト（次の一手がない・長く残っている項目・作業のヒント）・停滞・連絡待ち・期日・いつかやるを1段ずつ点検し、その場で採用・完了・休止などを選べます。今週の気づきがあるときは最初の段に出ます。今いる段はこの端末に残り、途中でやめても続きから再開できます（別の端末で見直しを報告したら最初からになります）。最後の段の「見直した」で、見直した日をVaultに記録します。ホームには前回からの日数が出て、7日以上空くと強調します（通知は出しません）。報告するのは本人だけで、AIは報告しません。対応した本体が必要です。
- **繰り返す作業を定例にする**: 「日付を付ける」で期日に繰り返し（毎日・毎週・2週ごと・毎月・3か月ごと）を選べます。定例の項目には「今回を完了」「今回は見送る」が出て、押すと項目は欄に残ったまま期日が次の回へ進みます（遅れて片付けても過ぎた回はためません）。定例をやめるときは「定例を終える」で項目を片付けるか、繰り返しを「なし」にします。対応した本体が必要です。
- **記録に聞く**: メニューの「記録に聞く」から「前にこの件はどう決めたか」のような問いを送ると、Mac miniの本体が次の整理のときに、Vaultのメモと作業要約だけを根拠に答えます。答えの文ごとに根拠の記録と記録からそのまま写した引用が付き、元の記録を開けます。プロジェクトを選ぶと、そのプロジェクトの記録だけから答えます。答えはAI生成・未検証で、メモにはなりません。問いは保存の前に秘密情報らしい文字列を確かめます。対応した本体が必要です（[本体の説明](https://github.com/mozuq-lab/context-hub/blob/main/docs/ask.md)）。
- **好みを端末間でそろえる（任意）**: 「設定」の「好みを端末間でそろえる」を有効にすると、ピン留めと並び順・メモのひな形（このVaultでの既定のプロジェクトを含む）・文脈かごの上限を、同じVaultを使うMacとAndroidでそろえます。変えたときに受付ファイルでMiniへ送り、Miniがまとまりごとに新しい方を残します。ほかの端末は読み込んだときに取り込みます。有効にするとき、この端末の設定でそろえるか、Vaultにある設定を使うかを選べます。既読・ウインドウ・通知・APIキーは送りません。ひな形に秘密情報らしい文字列があるとき、ひな形の合計が大きすぎるときは、ひな形は送らずに知らせます。Vaultごとに選び、既定は無効です。対応した本体が必要です。
- **期日をカレンダーに入れる（Android・Mac）**: 期日を付けた項目の「カレンダーに入れる」から、その日の終日の予定として端末のカレンダーに渡します。Androidは予定の作成画面を開き、Macは予定1件のファイルをカレンダーで開くので、保存するかはカレンダーで決めます（アプリはカレンダーの権限を取りません）。件名と説明には伏せ字の規則を当て、規則を確かめられないときは渡しません。本体の設定で予定に本文を入れないようにしている（`calendar.titles: project`）ときは、件名をプロジェクト名と「次の一手」「未解決」だけにします。Macでは予定1件のファイルを一時フォルダーに置いたままにします（同じ項目は上書きし、OSが一時フォルダーを片付けます）。予定の識別子は本体のカレンダー用ファイル（`90_system/calendar/contexthub.ics`）と同じなので、後から本体のファイルを読み込んでも同じ予定として扱われます。
- **プロジェクトの経緯を読む**: プロジェクト画面の「これまでの経緯」から、本体が生成する月ごとの経緯（届いた入力、現在地の移り変わり、完了・解決、状態の切り替え、採用した方針）を読めます。休止から戻るときや完了にするときの確認に使います。各行から元のメモへたどれます。
- **プロジェクトの資料を見返す**: 「あとで読む」「この仕様を見た」と書き留めたメモのうち、AIが参考資料に分類したものを、プロジェクト画面の「資料」でURLと一緒に新しい順に読めます（本体が生成する一覧で、URLは押したときだけ外部のブラウザで開きます）。検索の種類「資料」でも絞り込めます。
- **同じものを指す2つのプロジェクトを1つにまとめる**: プロジェクト画面の「ほかのプロジェクトへ統合」から、統合先を選んで依頼できます。統合元は「統合済み」としてホームの後ろにまとまり、統合元を指定したメモ・完了報告・日付は統合先のものとして読みます。原文と記録は書き換えず、統合元の画面から取り消せます。
- **次の一手を自分で足す**: プロジェクト画面と「次の一手」画面の「次の一手を追加」から、自分で決めた行動を1行（200文字以内）で次の一手に載せられます。AIは整理せず、本人の言葉のまま「本人が追加: 」として載り、完了か誤りとして外すと報告するまで、新しい作業要約が届いても残ります。AIが読み取った次の一手や「提案」の行は「自分の行動にする」で文面を直して引き取れ、元の行はAIの読み取りの欄から外れます。Miniに届いてNOWに反映されるまでは「反映待ち」として示します。対応した本体が必要です。自分で足した行動は「…」の「プロジェクトへ移す」「別の置き場へ移す」で、プロジェクト未定から進行中のプロジェクトへ（プロジェクトから別のプロジェクト・プロジェクト未定へも）移せ、付けていた期日・手間の目安・連絡待ち・「いつかやる」も引き継がれます（行動を移す操作に対応した本体が必要です）。
- **次の一手・未解決を片付ける**: NOWの「次の一手」を完了に、「未解決」を解決にする報告ができます。片付けた項目は「解決済み・完了」にまとまり、未解決に戻すこともできます。
- **AIの読み違いを「誤り」として外す**: 次の一手・未解決の「誤りとして外す」から、理由（読み違い・別のプロジェクトの話・もう古い）と任意の一言を選んで報告できます。完了・解決には数えず、「誤りとして外した項目」にまとまり、未解決に戻せます。読み違いは本体が次の整理でそのメモを読み直し、AIが推定した関連付けへの「別のプロジェクトの話」は、そのメモをプロジェクトから外して関連先を見直します（プロジェクトを指定して保存したメモは、関連付けを変えず項目だけを外します）。外した項目の本文・理由・一言は、同じ読み違いを減らすために、本体が次からの整理でAIへ渡します。対応した本体が必要です。
- **「片付いたかも」を確かめる**: プロジェクトを指定して保存したメモに、次の一手や未解決が片付いたと読める記述があると、本体の整理でAIが候補として示します（AIの推定で、まだ完了・解決ではありません）。項目の下に根拠のメモの引用が出るので、合っていれば「完了にする」「解決にする」で報告し、違えば「違う」で見送ります。見送った候補は、同じメモからは出ません。対応した本体が必要です。
- **バックアップから復元できるかを知る**: 本体の`ctx backup verify`が残した確認結果から、ホームに「最後に確かめた復元点」（いつのバックアップを、いつ確かめたか）を示します。最後の確認で復元できなかったとき、確かめた復元点が本体の目安より古いときは知らせます。確認結果がなければ何も出しません。アプリはバックアップの作成も確認もしません。
- **前回見てからの変化に気づく**: プロジェクトを最後に開いたときから増えた項目・外れた項目を、一覧の印とプロジェクト画面の「NEW」で示します。既読の記録はこの端末だけに保存し、Vaultには書きません。
- **コミット履歴の下書きを使う**: 本体で設定したリポジトリのコミット件名から作られた作業記録の下書きを確認し、本文を編集して入力にするか、見送ります。
- **新しいプロジェクトを作る**: メニューの「プロジェクト」の見出しの＋（新しいプロジェクト）から、名前・別名・キーワードと最初のメモを入れて作成を依頼できます。名前・別名が既存のプロジェクトと重なる場合は送る前に知らせます。定義が届くまでは「作成依頼中」と表示します。
- **止まったNOWを生成版に戻す**: NOWの自動で作られる部分を手で書き換えると、本体はそのNOWを上書きしなくなり、更新が止まります。プロジェクト画面にそのことと手で変えた行を表示し、「生成版に戻す」を依頼できます。手で変えた行は、戻す前にそのプロジェクトのメモとして残ります。
- **同期で届いた変更を自動で読み込む**: アプリを前面に戻したとき（前の読込から20秒以上たっていれば）と、前面に出している間の1分おきに、Vaultのファイルが変わっていないかを確かめ、変わっていれば読み込み直します。変わっていなければ表示はそのままです。入力・確認の途中や読込中は読み込まず、次の機会に回します。読み込めなかったときは前の表示を残し、知らせません（「再読込」を押すと理由を示します）。この端末から保存したメモ・訂正が、Miniで受け付けられた・整理された・うまくいかなかったと分かると、画面下で知らせます（アプリを開いている間に保存したものだけで、知らせは1段階につき1回です）。「設定」の「同期した変更を自動で読み込む」で止められます（この端末の設定です）。同期そのものは今までどおり同期アプリが行います。
- **メモを追加する**: 思いつきのメモや、AIとの作業要約をVaultの `Input/` へ追加します。入力中の本文はこの端末に自動で残し、フォームを閉じたりアプリが終了されたりしても、次に開いたときに続きから書けます（保存が確かめられたら消えます。Vaultには書きません。フォームの「書きかけをこの端末に残す」で止められます。止めても、保存中にアプリが終わったときに二重に保存しないよう、保存を試みた操作IDだけは本文なしで残します）。
- **昨日のことを今日書く（出来事の日付）**: メモの入力画面の「いつのこと」で、昨日・おととい・日付を選ぶと、そのメモを「いつのことか」の日付で並べ、書いた日時は記録日時として別に残します（今日と今日より後、本体の設定の日数（既定1年）より前は選べません）。記録の詳細には「YYYY-MM-DDのこと（…に記録）」と出ます。対応した本体が必要で、本体が対応を書き出していないときは選択肢を出しません。
- **ひな形から書く**: メモの入力画面の「ひな形」から、会議・不具合・読んだもの・作業の区切りの見出しを本文へ差し込めます。中身を書かなかった見出しは保存前に取り除くので、空の見出しがAIに読まれません。ひな形は追加・編集・並べ替えでき、Vaultごとに既定のプロジェクトを決められます。この端末だけに保存し、Vaultには書きません。
- **選びながら記録・壁打ちする（任意・Claude APIを使用）**: 「選んで深掘り」を開くと、AIが1問ずつ問いと選択肢を出し、選ぶだけで作業の記録・迷いごとの整理・アイデア出しを進められます。合う選択肢がなければ一言で答えたり、「わからない」「戻る」「ここでまとめる」を選んだりできます。最後にAIが書いたまとめを確かめて直し、問答の記録を付けたメモとしてInputへ保存します。使うにはAnthropicのAPIキーが必要です（[選んで深掘り](#選んで深掘りclaude-apiを使う)）。
- **秘密情報らしい文字列に気づく**: メモ・訂正・新しいプロジェクトの最初のメモ・「選んで深掘り」のまとめを保存する前に、APIキー・トークン・パスワード・秘密鍵らしい文字列が見つかると種類を知らせます。「戻って直す」「伏せ字にして保存」「そのまま保存」から選べます。「選んで深掘り」でClaude APIへ送る資料と答え、コピーするcontext、文脈かごの「まとめてコピー」では、同じ規則で`[伏せ字:APIキー]`のように置き換えます。本体の設定で追加した規則（本体が`90_system/privacy/patterns.json`に書き出したもの）も当てます。追加した規則を確かめられないときは、「選んで深掘り」を始めず、contextのコピーも止めて理由を示します。決まった規則による検出のため、見逃しも誤検出もありえます。
- **似ているアイデアを束ねる**: アイデアの画面に、本体が見つけた似ているアイデアを表示します。「同じ話として束ねる」「別の話」を確認して依頼でき、束ねたアイデアは一覧に印が付きます。直接束ねた組は「束から外す」で戻せます。アイデアの本文は書き換えません。
- **ホーム画面から開く（Android）**: アプリのアイコンを長押しすると「メモを追加」「選んで深掘り」「次の一手」を直接開けます。ホーム画面ウィジェットは、次の一手と確認待ちの件数、読込時刻を表示し、「メモを追加」を開けます。ホーム画面は周りの人からも見えるため、既定では件数だけです。「設定」の「ウィジェットの表示」で、次の一手の本文（3件まで）とプロジェクト名を出すか、対象のプロジェクトを選べます。期日が7日以内の項目を先に並べ、見直す日が先の項目は数えず出しません（「次の一手」の画面と同じ扱いです）。表示設定はVaultごとに持ちます。表示はアプリで読み込んだ時点の内容で、日付の区分も含めて、アプリを開くと更新されます。
- **判断待ちに気づく**: メニューの「確認待ち」に、採用・却下を待つ候補の件数を出します。同じ対象を指すプロジェクト案は、1組を1件と数えます。作業記録の下書きや、手で書き換えて更新が止まったNOWがあるプロジェクトにも、メニューに件数を出します。その画面を最後に開いた後に増えた分は「新着」と色で示し、画面を開くと件数だけに戻ります。「保存と反映」には、この端末で保存を確かめられていない操作の件数を出します。Macでは、ドックのアイコンにも判断待ちの合計を出します（アプリで最後に読み込んだ時点の件数です）。この端末から採用・却下などを依頼して反映を待っているものは数えません（ホームの「確認待ち」の件数には含まれます）。似ているアイデアと「片付いたかも」は数えません。既読の記録はこの端末だけに保存し、Vaultには書きません。
- **アプリを閉じている間に確認待ちが増えたら通知する（Android・任意）**: 「設定」の「確認待ちの通知」を有効にすると、数時間おきに端末に同期済みのVaultを読み、候補・作業記録の下書き・止まったNOWが増えたときだけ通知します。通知に出すのは件数と種類だけで、本文は出しません。通知を押すと、直近に増えた判断待ちを判断できる画面（候補なら「確認待ち」、下書きや止まったNOWならそのプロジェクト）が開きます。既定は無効で、有効にしたときに端末の通知の許可を求めます。読むのは端末内のフォルダーだけで、ネットワークには接続しません。同期が遅れていると通知も遅れます。Vaultを読み切れないとき（画面に読取の注意が出ているとき）は通知しません。確認の間隔は端末の省電力の都合で延びることがあります。端末の設定で通知を止めると確認も止まり、「確認待ちの通知」の画面でそのことを示します。端末を再起動した後は、アプリを一度開くと確認を再開します。
- **候補を確認して採用・却下する**: AIが提案したプロジェクト案・知識・方針の候補を読み、採用・却下を依頼できます。名前や別名が重なるプロジェクト案は本体が1組にまとめ、代表の1件として根拠のメモの件数とともに並びます。代表を採用・却下すると、まとめた案にも同じ判断を依頼します（別の取り組みの案はチェックを外して判断から外せます。1件ずつ判断することもできます）。Miniが受け付けられなかった依頼は候補に示し、もう一度判断できます。方針は、元のメモでの指定やAIの推定を確認したうえで、共通にするか特定のプロジェクトに限るか（採用先）を選んで採用でき、採用履歴から適用停止も依頼できます。詳しくは[候補確認の使い方](docs/candidate-review.md)と[本体の方針の説明](https://github.com/mozuq-lab/context-hub/blob/main/docs/policies.md)を参照してください。
- **採用した方針を見直す**: 採用から（または前回確かめてから）本体の設定の日数（既定90日）が過ぎた方針（判断・好み）は、判断履歴の行に「見直す時期」と出ます。詳細の「まだ有効」で、今の内容のまま続けることを記録し、日数を数え直します。やめるなら適用停止します。「まだ有効」は確かめた内容に結び付けて送り、その後に内容が変わっていれば本体が断ります。対応した本体が必要です。

アプリが行うのは「依頼をInputへ保存する」ところまでです。採用後の正式なデータの作成や整理、プロジェクトの状態の反映は、Mac mini側の本体が行います。ふりかえり・状態の切り替え・完了報告・期日と見直す日・経緯・資料・プロジェクトの統合・下書き・呼び名とキーワードの変更・望む結果・似ているアイデアの表示と束ねる依頼・人ごとの見返しには、それらに対応した本体が必要です。原文の書き換え（訂正は元のメモを残した追加として送ります）や生成された要約の編集、自由入力のAIとのチャット、同期やモデル・Gatewayの設定はアプリに含みません。アプリがネットワークへ接続するのは、本人が始めた「選んで深掘り」の問いとまとめの作成だけです。

## 画面の移動とウインドウ

画面は使う頻度で並べています。広い画面（Mac）では左のサイドバーの上に検索欄と「メモを追加」「質問に答えてまとめる」を置き、その下に毎日使う画面（ホーム・次の一手・確認待ち・最近のメモ）、プロジェクト、ときどき使う画面（ふりかえり・いつかやる・アイデア・人・記録に聞く・文脈かご）の順に並べます。狭い画面（Android）では、毎日使う4つの画面を下のタブに置き、それ以外は「その他」から開きます。メモの追加は右下のボタン、検索は上の虫めがねから行います。保存と反映と「設定」（Vaultの選び直し・自動の読み込み・ウィジェット・通知・好みの同期・キーボード操作・このアプリについて）は、メニューのいちばん下にまとめています。

記録や候補の詳細は、メニューを残したまま本文の領域に開きます。詳細を開いたままメニュー・下のタブ・プロジェクトを選ぶと、「戻る」を押さずにその画面へ移れます（キーボードの移動キーも使えます）。Androidの「戻る」は、開いている詳細を先に閉じます。

Macでは、ウインドウの位置と大きさを覚え、次に起動したときに戻します（初めての起動では、メニューが横に出る大きさで画面の中央に開きます）。画面下に出る案内は、続けて出たときに前の案内を待たず、新しい案内に置き換えます。

## キーボード操作

Macでは⌘、Androidの物理キーボードではCtrlを使います。Macではメニューバー（ファイル・編集・移動・ウインドウ・ヘルプ）からも同じ操作を選べます。一覧は⌘/、Macのヘルプメニュー、または広い画面の「設定」の「キーボード操作」から開けます。

| キー（Mac） | 操作 |
|---|---|
| ⌘N | メモを追加 |
| ⇧⌘N | 質問に答えてまとめる |
| ⌘F | 検索を開いて入力欄へ |
| ⌘R | 再読込 |
| ⌘1〜⌘8 | ホーム・次の一手・確認待ち・最近のメモ・ふりかえり・アイデア・検索・保存と反映 |
| ⌘, | 設定 |
| ⇧⌘C | 表示中のプロジェクトの出典付きcontextをコピー |
| ⌘Return | メモ・訂正のフォームで保存 |
| Esc | メモ・訂正のフォームを閉じる（本文が空、または訂正文を書き換えていないときだけ） |
| ⌘/ | キーボード操作の一覧 |

フォームや確認を開いている間は、画面の移動やメニューの操作は受け付けません。書きかけがあるフォームはEscでは閉じないので、「フォームを閉じる」を使ってください。Macではメモ・訂正のフォームを開くと本文の入力欄へ移ります。Macのメニューバーはアプリ独自のものに置き換わるため、「編集」には取り消す・やり直す・カット・コピー・ペースト・すべてを選択だけを並べています。

## 使う前に必要なもの

アプリだけでは動きません。次の環境が別に必要です。

1. **ContextHub本体**: 常時稼働するMac miniなどで、受付と整理を行います。導入は[本体のREADME](https://github.com/mozuq-lab/context-hub)を参照してください。
2. **同期の仕組み**: Syncthingなどで、Vaultフォルダーを端末とMac miniの間で同期します。アプリ自体は同期を行いません。
3. **端末上の同期済みVault**: アプリでは、端末に同期されたVaultのフォルダーを選びます。

まず動作だけ確認したい場合は、アプリ内の「サンプルで試す」で架空のデータを表示できます。この場合、上の環境は不要です。

## 使い方

### インストール

**先にビルドが必要です。** ビルド済みのアプリはこのリポジトリでは配布していません。下の「[ビルド方法](#ビルド方法)」で作成してください。

- **Mac**: `artifacts/ContextHub Flutter.app` をFinderから開きます。ターミナルから起動する必要はありません。
- **Android**: `artifacts/context-hub-flutter-android.apk` を端末に転送してインストールします。このAPKは手元で使うための署名で、Playストアでは配布していません。実機のAndroid端末へのインストールは、まだ検証していません。

### 基本の流れ

1. 初回は「サンプルで試す」で、架空のVaultを使って画面を確認できます。
2. 「Vaultフォルダーを選ぶ」で、同期済みVaultの最上位のフォルダー（`Input/` や `90_system/` があるフォルダー）を選びます。Androidでは端末内のローカルフォルダーを選んでアクセスを許可してください。クラウドストレージやストレージ全体のルートは選べません。Macでは、ハードリンクを作れない保存先（exFAT・FATでフォーマットした外付けドライブなど）のVaultへは保存できません（閲覧はできます）。APFSかMac OS拡張の保存先を使ってください。
3. 左側のサイドバー（画面が狭いときは下のタブと「その他」）から、ホーム・次の一手・確認待ち・最近のメモ・各プロジェクトなどを開きます。
4. 「メモを追加」で、思いつきや作業要約を書いて保存します（1〜8000文字、プロジェクトの指定は任意）。雑なメモで構いません。AIの作業要約は未検証の内容として扱われます。
5. 同期が進むと、アプリが自動で読み込み直し、保存したメモがMiniで受け付けられたり整理されたりしたら画面下で知らせます。すぐに確かめたいときは「再読込」を押し、「受付状況」でMini側に受け付けられたかを確認します。

### メモが整理されるまでの段階

メモは次の順に進みます。アプリで保存できても、整理まで終わったとは限りません。

| 段階 | 誰が行うか |
|---|---|
| 1. この端末のInputに保存 | アプリ |
| 2. Mac miniへ同期 | Syncthingなどの同期アプリ |
| 3. Miniで受領 | ContextHub本体 |
| 4. 整理済み | ContextHub本体 |

アプリが表示する読込時刻は、同期が完了した時刻ではありません。Androidでは、同期アプリがアクセスできる場所にあるVaultを選んでください。「サンプルで試す」のデータはアプリ専用の領域にあり、同期されません。

### 注意点

- **要約はAIが作った未検証の内容です。** 大事な判断の前には、元のメモ・出典・訂正の注意を確認してください。
- **文脈には有効な方針も含まれます。** コピーする内容には、共通と対象プロジェクトの有効な方針が全文入ります。方針が未同期の場合はコピーを止めます。
- **コピーが止まることがあります。** コピーの直前に記録が変わった場合や、壊れた記録・整合性を確認できない記録がある場合、表示を更新してコピーを止めます。内容を確認してからもう一度コピーしてください。ただし、本人のInput・アイデア・資料に入らないほかのプロジェクトのフォルダーだけの問題では止めません。同期ソフトの競合コピー（`.sync-conflict-`を含む名前）は、本体と同じく通常の記録から外して注意を出し、コピーは止めません（方針の正本の中にある競合コピーは、本体の方針の集約も止まるため、方針の未同期として止めます）。
- **保存結果がわからないときは、同じ内容を送り直さないでください。** 「保存確認待ち」と表示されたら、フォームを開いたまま「同じ操作を確認」を押します。フォームを閉じた後は「受付状況」から確認できます。保存結果を確かめられないまま閉じた書きかけは、次に「メモを追加」を開くと「同じ操作を確認」から再開します（確認するまでは、その書きかけを閉じて新しく書くことはできません）。
- **アプリのデータやInputを削除してやり直さないでください。** 確認情報が壊れた場合、アプリは新しい保存を止めますが、閲覧はできます。復旧の前に[データと権限](SECURITY.md)を読んでください。

## 選んで深掘り（Claude APIを使う）

頭の中でまとめてから書く代わりに、AIの問いに選択肢で答えながら記録や壁打ちを進める機能です。使わなければ、アプリはこれまでどおりネットワークへ接続しません。

1. サイドバーの「質問に答えてまとめる」（画面が狭いときは下のタブの「その他」）か、プロジェクト画面の「このプロジェクトで深掘り」を押します。
2. 初回は右上の「AIの設定」で、AnthropicのAPIキーを登録します。キーはAnthropicのConsoleで発行します。
3. 目的（記録・壁打ち・アイデア）、プロジェクト（任意）、きっかけの一言（任意）を選び、「始める」を押します。
4. 問いに選択肢で答えます。合うものがなければ「その他（一言）」、答えられなければ「わからない」を押します。前の問いへは「戻る」か、答えたチップから戻れます。3〜6問ほどで「ここでまとめる」を押すか、10問に答えると自動でまとめに進みます。
5. AIが書いたまとめを確かめて直し、「Inputへ保存」を押します。メモの最後には、どの選択肢を選んだか、どこを自分の言葉で書いたかが分かる問答の記録が付きます。

| 項目 | 内容 |
|---|---|
| 送り先 | AnthropicのClaude API（`api.anthropic.com`）。端末から直接送り、Mac miniなどは経由しません |
| 送る内容 | 目的・きっかけ・それまでの問答。「Vaultの資料もAIへ送る」（既定はオフ）をオンにすると、資料（最大4000字）も送ります。資料は、プロジェクトを選んだときはその名前・方針・現在地・次の一手・未解決・提案・関連するメモ（未整理・整理失敗を含む）、選ばないときは共通方針・進行中のプロジェクトの名前とID・最近のメモ5件です。資料を送るときは、選んだプロジェクトの名前とIDも送ります。オンにすると、送る資料の全文をその場で開いて示します。オフにすると、プロジェクトの名前を含めVaultの内容は送りません |
| Vaultへの書込 | 「Inputへ保存」を押したときだけ、通常のメモとして追加します。途中の問答は端末の`guided.json`に残し、閉じても続きから再開できます |
| APIキーの保管 | Macはキーチェーン、AndroidはAndroid Keystoreの鍵で暗号化したアプリ専用領域。Vault・同期フォルダー・ログには書きません |
| 料金 | Anthropicの契約に応じてかかります。1回の深掘りで、問いの数＋1回ほど呼び出します。「AIの設定」で月の呼び出し上限（既定200回）を決められ、今月の回数とトークン数（モデル別・キャッシュの書込と読取を分けた内訳）と、アプリに持つ料金表による概算額（目安）を確認できます。応答が途中で途切れた呼び出しは、届いた分だけを数え、費用が発生した可能性がある回数として別に示します |
| モデル | アプリで固定しています（「AIの設定」に表示）。安全上の理由でこのモデルが応答を控えたときは、Anthropic側で別のモデルが代わりに答えることがあります。実際に応答したモデルはメモに記録します |

- **AIのまとめは下書きです。** 問答にない事実を足さないように頼んでいますが、保存する前に読んで直してください。保存したメモは本人のメモとして整理されます。
- **選択肢はAIの提案です。** 合わないときは「その他（一言）」で自分の言葉にしてください。
- 保存したメモには、`capture_mode: guided`・目的・問いの数・応答したモデル・資料の範囲（プロジェクトの資料を送ったときは、そのプロジェクトのIDも。確認画面で保存先を変えても区別できます）を`meta`として付けます。
- APIキーは「選んで深掘り」を開いたときに1回だけ読み、画面を閉じるまでメモリに持ちます。Macでアプリをビルドし直したあとなどに、キーチェーンへのアクセスを確かめる画面が出たら「常に許可」を選んでください（「許可」だと、開くたびに確かめられます）。拒否したときは「もう一度読み出す」を押すか、APIキーを登録し直してください。
- 実際のClaude APIとの通信と、キーチェーン・Keystoreでの保管は、まだ実機で検証していません（[検証状況](docs/verification.md)）。

## ビルド方法

### 必要なもの

| 対象 | 必要なもの |
|---|---|
| 共通 | Flutter 3.47.9（Dart 3.13.7）、Makefileを使う場合はmake |
| Mac | Xcode |
| Android | Android SDK、JDK 21 |
| 動作確認（`scripts/verify.sh`） | 上記に加えてNode 24とnpm、ネットワーク接続（依存の取得）。Macではpython3も使います |

Nodeはビルド前の検証にだけ使います。端末でアプリを使うときには不要です。

### 手順

```sh
git clone --recurse-submodules https://github.com/mozuq-lab/context-hub-flutter-client.git
cd context-hub-flutter-client
make verify                 # 静的解析とテスト（任意）
make android                # → artifacts/context-hub-flutter-android.apk
make macos                  # → artifacts/ContextHub Flutter.app とMac版ZIP（Macでのみ実行可）
```

`make` または `make help` でコマンド一覧を表示します。既存の `scripts/verify.sh`・`scripts/build.sh [all|macos|android]` も利用できます。`scripts/build.sh` を引数なしで実行すると、AndroidとMacの両方をビルドします（Macでのみ実行できます）。

通常のMac版ZIPは `artifacts/context-hub-flutter-macos.zip` に保存します。

### MacのDeveloper ID署名

通常の `make macos` はad-hoc署名です。Developer ID Application証明書がキーチェーンにある場合は、証明書の名前またはhashを実行時の環境変数 `MACOS_SIGN_IDENTITY` に指定して `make macos-signed` を実行します。証明書は `security find-identity -v -p codesigning` で確認できます。

```sh
MACOS_SIGN_IDENTITY='署名証明書のhash' make macos-signed
```

署名検証後のアプリは `artifacts/ContextHub Flutter.app`、ZIPは `artifacts/context-hub-flutter-macos-developer-id.zip` に保存します。証明書名・Team ID・個人の絶対パスをMakefileや設定ファイルへ記載する必要はありません。署名済みアプリ自体には証明書の名義などが含まれます。名義を含めたくない場合は、通常の `make macos` を使ってください。

署名時はAppleのタイムスタンプサーバーへ接続し、取得失敗時は停止します。ローカル確認用にタイムスタンプを付けない場合だけ、明示的に `MACOS_TIMESTAMP=none` を追加します。公証や公開は実行しません。

署名検証とZIPの作成が成功してから、`artifacts/` のMac版を更新します。

### うまくいかないとき

- FlutterがPATHにない場合は、`FLUTTER_BIN=/path/to/flutter scripts/build.sh android` のように指定します。
- AndroidでJDKが見つからない場合は、`JAVA_HOME` をAndroid Studio内のJDKへ指定します。
- Macで使うXcodeを指定したい場合は、`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` を指定します。グローバルのXcode設定を切り替える必要はありません。
- Xcodeがworkspaceを認識しない場合は、`MACOS_BUILD_METHOD=project make macos` で同じRelease設定のprojectビルドを使えます。署名付きビルドにも同じ変数を指定できます。
- Xcodeの利用規約が未承諾というエラーが出た場合は、ターミナルで `sudo env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -license` を実行し、内容を確認して同意してください。スクリプトは規約に自動で同意しません。

### Androidの署名鍵について

Androidのビルドでは、このclone（取得したフォルダー）専用の検証用の鍵を `.local-signing/` に作ります。同じアプリを上書き更新し続けるには、この鍵を残しておいてください。鍵を作り直すと、インストール済みのアプリを上書きできなくなります。この鍵は公開配布用ではなく、Gitにも含めません。

Playストアでの配布とMacの公証には対応していません。
